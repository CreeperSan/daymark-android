## Purpose

提供对常见 API 数据格式、文件传输和持续事件连接的一致访问方式，并以可观测进度和明确资源所有权保障大载荷传输可靠性。

## ADDED Requirements

### Requirement: 常规请求载荷可正确编码和解码
系统 SHALL 支持 JSON、URL 编码表单、Multipart 表单、Protocol Buffers 和原始二进制请求与响应。系统 MUST 根据调用方指定或服务端声明的媒体类型选择匹配的编解码方式，并对不支持或不匹配的媒体类型报告结构化失败。

#### Scenario: 发送 JSON 请求并解析 JSON 响应
- **WHEN** 调用方发送 JSON 载荷且服务端返回匹配的 JSON 响应
- **THEN** 系统以声明的目标类型提供已解析的成功数据

#### Scenario: 发送包含文件的 Multipart 表单
- **WHEN** 调用方提供文本字段和一个或多个文件部分
- **THEN** 系统以 Multipart 格式发送全部部分并保留各部分的媒体类型和文件名

#### Scenario: 处理 Protocol Buffers 响应
- **WHEN** 服务端返回声明为 Protocol Buffers 的有效响应
- **THEN** 系统使用调用方提供的消息类型解码并提供成功数据

### Requirement: 上传和下载报告单调进度
系统 SHALL 为可确定总长度的文件上传和下载报告已传输字节、总字节和百分比进度；进度 MUST 单调递增且不得在终态后继续发出。总长度未知时系统 SHALL 明确标识总量不可用，而非伪造百分比。

#### Scenario: 上传文件时报告进度
- **WHEN** 调用方收集一个具有已知大小的文件上传事件流
- **THEN** 在开始与终态之间收到单调递增的上传进度事件

#### Scenario: 下载响应未提供内容长度
- **WHEN** 调用方下载未声明总长度的响应
- **THEN** 进度事件包含已传输字节并标识总长度未知

### Requirement: 文件下载安全写入并支持恢复策略
系统 SHALL 将下载数据写入调用方指定的目标位置，并在正常完成前使用临时目标防止半成品被误认为完成文件。调用方启用恢复策略且目标存在有效部分文件时，系统 SHALL 请求并验证可恢复的范围传输；验证失败时 SHALL 按声明策略重新下载或报告失败。

#### Scenario: 下载成功后原子提交目标文件
- **WHEN** 文件下载完整且校验通过
- **THEN** 系统将临时文件提交为目标文件并报告成功

#### Scenario: 部分文件无法恢复
- **WHEN** 调用方启用恢复策略但服务端不接受范围请求
- **THEN** 系统按调用方选择重新下载或报告恢复失败，且不将部分文件标记为完成

### Requirement: SSE 持续事件可解析、取消和重连
系统 SHALL 支持以服务端发送事件流建立持续连接，按协议边界提供事件名称、标识、数据和重连提示。调用方取消后系统 MUST 关闭连接；启用重连策略时，系统 SHALL 在可配置限制内使用最后事件标识恢复连接，并报告不可恢复错误。

#### Scenario: 接收连续 SSE 事件
- **WHEN** 服务端在持续连接上发送多个有效事件
- **THEN** 系统按照接收顺序将每个事件提供给数据流

#### Scenario: 取消 SSE 收集
- **WHEN** 调用方取消正在收集的 SSE 数据流
- **THEN** 系统关闭持续连接且不再提供后续事件
