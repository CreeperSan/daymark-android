## Context

本变更按全新工程设计，不迁移旧网络代码，也不提供兼容层。框架需要同时表达一次性响应、持续字节流和 SSE 长连接；普通请求与流式请求共享请求描述、中间件和传输抽象，但不能共享相同的终态语义。

## Goals / Non-Goals

**Goals:**

- 建立不暴露 OkHttp、Retrofit 或序列化库类型的稳定核心 API。
- 使用不可变请求配置、类型化属性和每次执行独立上下文。
- 支持全局/请求级可挂起中间件、请求改写、响应回程处理和短路。
- 以冷 Flow 提供普通请求、上传下载进度、原始字节流和 SSE 消息。
- 保证结构化取消、资源只释放一次、流式读取有背压。
- 提供可替换传输引擎，首个实现使用 OkHttp。

**Non-Goals:**

- 不在基础框架中内置业务鉴权协议、业务码规则、缓存策略或无限重试。
- 不把 SSE 消息转换成一次性 JSON 响应。
- 不将完整大文件或长响应聚合为 ByteArray。
- 不强制使用 Retrofit 作为动态请求核心。

## Decisions

### 1. 分层与公开边界

公开 API 分为 request、middleware、transport、stream 和 codec 五个概念域。`NetworkManager` 负责组装配置、快照全局中间件并创建 `RequestCall`、`ByteStreamCall` 或 `SseCall`；核心层只接受自定义 `TransportEngine`。

传输接口提供一次性执行和流式打开两类能力：

```text
execute(request) -> RawResponse
openStream(request) -> NetworkStream
```

OkHttp 适配器负责将调用取消映射到 `Call.cancel()`，并将响应体包装成可关闭的字节源。未来可增加 Ktor、测试模拟或其他实现而不改变请求和中间件 API。

### 2. 请求与上下文不可变/可变分离

`NetworkRequest` 使用只读 Map、List 和不可变 body 描述，构造时复制外部集合。执行时创建 `RequestContext`，其中保存 requestId、开始时间、重试计数、最近 SSE id 和类型化属性。请求配置可复用，上下文不可跨执行共享。

类型化属性使用 `AttributeKey<T>`，避免中间件依赖字符串键和不安全强转；敏感属性只允许通过受控接口读取，日志器默认脱敏。

### 3. 中间件链模型

全局中间件注册器使用原子快照，单次请求固定使用注册时的列表。链顺序为：

```text
全局 1 -> 全局 2 -> 请求 1 -> 请求 2 -> Transport
Transport -> 请求 2 -> 请求 1 -> 全局 2 -> 全局 1
```

中间件以挂起函数接收 `proceed(request, context)`，可在 proceed 前等待和改写请求，也可在返回后转换响应或映射失败。缓存命中、策略拒绝和取消使用显式控制结果，不通过 null 或异常吞掉流程。

### 4. 三种执行模型

普通请求产生 `NetworkEvent<T>`，终态为成功、失败或取消；原始流产生有序 `ByteChunk` 与进度事件；SSE 产生 `SseMessage<T>`，连接可以长期不结束。三者均为冷 Flow，收集即执行，取消即关闭。

不使用一个巨型泛型事件封装所有模式，避免普通请求的单次成功语义污染 SSE 的持续消息语义。`ResponseMode` 只用于请求校验和传输选择，调用入口仍以不同 Call 类型表达能力边界。

### 5. SSE 解析与重连

SSE 解析器在 `Dispatchers.IO` 上逐行读取 UTF-8 内容，聚合 data 行，遇空行提交事件；注释行作为心跳处理但不交付业务消息。解析器只负责协议，不负责业务模型；`SseEventDecoder<T>` 负责数据转换。

重连属于 SSE 专用策略，不复用普通 HTTP 重试。默认关闭；开启时限定最大次数/总时长，采用指数退避，并仅对连接断开等可恢复错误重连。最近已交付事件 ID 存入执行上下文，重连请求加入 `Last-Event-ID`。401、403、404 等明确不可恢复状态不无限重连。

### 6. 流式传输和文件安全

原始流以固定缓冲区读取并通过 Flow 背压；进度包装器按最小时间或字节增量采样。下载到文件时先写同目录临时文件，成功后校验长度或摘要，再执行原子移动。取消和失败关闭源、输出流和底层调用，目标文件不被半成品覆盖。

### 7. 解码与错误

响应解码器独立于传输和中间件，支持 JSON、文本、二进制和自定义协议。错误为密封分类，包含 requestId、HTTP 状态或业务码等安全诊断字段以及原始原因引用；默认字符串和日志不包含认证头、Cookie、密码、完整 body 或文件内容。

## Risks / Trade-offs

- [长连接占用资源时间不可预测] → 强制绑定收集协程，提供显式取消和连接上限配置。
- [SSE 重连造成重复消息] → 保存 Last-Event-ID，并将去重策略作为可选消息操作器，不默认丢弃业务消息。
- [高频进度事件造成背压] → 时间/字节双阈值采样，终态前补发最终进度。
- [不同传输实现语义不一致] → 以传输契约测试约束取消、关闭、状态码和响应头行为。
- [文件恢复污染临时数据] → 临时文件与目标文件分离，范围响应不符合预期时重新开始或显式失败。

## Migration Plan

1. 在新网络包中实现核心模型、传输 SPI 和 MockTransport，不触碰旧代码。
2. 实现 OkHttp 一次性请求、原始流和 SSE 适配，并用 MockWebServer 固化协议行为。
3. 完成中间件、错误、取消、进度和文件安全测试后，再接入第一个业务接口。
4. 业务接口直接采用新 API；旧网络实现不迁移、不适配。
5. 若新框架需要回滚，移除新模块装配和新业务调用即可，不影响旧业务数据。

## Open Questions

- 首个业务接口的 JSON 序列化库和业务响应 envelope 由业务变更确定，不改变本设计的 `ResponseDecoder` 边界。
