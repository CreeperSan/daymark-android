## Purpose

为应用提供可复用且可按服务、请求与业务场景独立配置的网络客户端，避免调用方依赖隐式全局状态或重复组装连接参数。

## ADDED Requirements

### Requirement: 网络客户端可显式配置和复用
系统 SHALL 允许调用方通过公开的构建入口创建命名或匿名网络客户端，并以不可变配置指定基础地址、连接与读写超时、默认请求头、响应转换策略和传输客户端。相同有效配置的客户端 SHALL 可被安全复用，且一个客户端的配置不得影响其他客户端。

#### Scenario: 创建带默认请求头的客户端
- **WHEN** 调用方以基础地址、超时和默认认证头创建客户端
- **THEN** 该客户端发出的每个请求均携带默认认证头，并使用指定的超时

#### Scenario: 单请求覆盖客户端默认值
- **WHEN** 调用方为一次请求提供与客户端默认值同名的请求头或超时
- **THEN** 仅该请求使用显式提供的值，客户端后续请求保持原默认配置

### Requirement: 请求描述支持常用参数
系统 SHALL 允许调用方通过请求描述或可选参数提供 HTTP 方法、路径、查询参数、请求头、标签、请求体和响应目标类型；缺失的可选参数 SHALL 不改变其他已配置参数的语义。

#### Scenario: 构造带查询参数的请求
- **WHEN** 调用方提供路径和多个查询参数
- **THEN** 请求以正确编码的查询参数发送，且未提供的参数不会出现在请求中

#### Scenario: 配置无请求体的读取请求
- **WHEN** 调用方仅提供读取方法和路径
- **THEN** 系统发送不含请求体的请求并返回对应的事件流

### Requirement: 配置失败可诊断
系统 MUST 在基础地址非法、超时非正数、载荷类型与请求体不兼容或缺少必要解码器时拒绝创建或执行请求，并向事件流提供包含原因与原始异常的结构化失败信息。

#### Scenario: 使用非法基础地址
- **WHEN** 调用方以不完整或不受支持的基础地址创建客户端
- **THEN** 系统不发起网络连接并提供可诊断的配置失败信息
